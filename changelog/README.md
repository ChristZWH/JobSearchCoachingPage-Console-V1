# Changelog 维护规范

> 每次功能改造 / 结构调整，在本目录新增一篇变更记录。同事要求建立，用于跨仓库（后端 / 前端 / 控制台）追踪项目级变更。

## 文件命名

```
YYYY-MM-DD-<英文短标识>.md     例：2026-10-01-student-case-filter-fields.md
```

- 日期用功能**完成（推送/提 PR）**的日期
- 一个功能一个文件；跨三仓库的改造写在同一篇里，按仓库分节

## 每篇必含的小节

1. **变更概述** —— 一两句话说清做了什么、为什么
2. **影响范围** —— 涉及的仓库、分支、PR 链接
3. **数据库变更** —— 加列/改表/迁移脚本路径；是否需要线上执行、执行顺序
4. **部署/上线步骤** —— 合并顺序、服务器操作、回填动作
5. **回滚方式** —— 出问题怎么退

## 其他约定

- 按**日期倒序**维护（新文件加进来即可，无需改旧文件）
- 数据库涉及删列、改列类型等**破坏性变更**时，在小节标题后加 `⚠️`
- 与飞书评审文档的关系：changelog 记"改了什么、怎么上"，方案细节（如表结构对比）以飞书文档为准，此处放链接即可
